# 05 · 术语表与概念边界

[专栏导读](./) · [参考资料](./references) · [来源与许可](./methodology)

> 整理自《从原理到业务的 AI 系统学习指南》，调研截止 2026 年 10 月 5 日。研究结论保留原有条件与来源；时效信息请结合原文日期阅读。

本表用于回查，完整机制和例子见第二、三板块。定义采用本文的工程语境；同一缩写在其他领域可能有不同含义。

| 术语 | 通俗解释 | 最容易混淆的边界 |
|---|---|---|
| AI 人工智能 | 让机器完成需要感知、推理、学习或行动能力的任务的研究与系统 | 包含规则、搜索等方法，不只机器学习 |
| ML 机器学习 | 从样本中学习规律以完成预测或决策 | 训练数据表现好不等于新数据表现好 |
| DL 深度学习 | 用多层可学习网络形成表示与任务能力 | 神经网络规模大不自动意味着业务价值高 |
| Foundation model 基础模型 | 在广泛数据上训练、可适配多个下游任务的模型 | 不一定只处理语言，也不意味着已适配具体业务 |
| LLM 大语言模型 | 以语言序列建模为核心的大规模模型 | 聊天产品还包含工具、检索和界面 |
| AIGC / Generative AI | 生成文本、图像、音频、视频等内容的技术及应用 | AIGC 常指生成内容与应用现象，不是单一架构 |
| Token 词元 | 模型处理序列的离散单位 | 不等于一个汉字、一个单词或一个字节 |
| Tokenizer 分词器 | 文本与 token ID 之间的编码规则 | 不同分词器改变长度与成本，不能通用估算 |
| Embedding 嵌入 | 把离散对象映射为可计算的向量 | 词嵌入、上下文向量和检索向量用途不同 |
| Attention 注意力 | 按查询与键的匹配权重聚合值的信息 | 权重不是人类注意，也不是可靠因果解释 |
| Transformer | 结合注意力、前馈网络、残差等的架构家族 | 原始编码器解码器与现代仅解码器 LLM 不同 |
| Parameter / Weight 参数/权重 | 训练时学到的数值 | 不是可直接查询和精确改写的数据库记录 |
| Context window 上下文窗口 | 一次处理可容纳的序列范围 | 标称长度不等于全部位置都能有效利用 |
| MoE 混合专家 | 用路由器让部分专家处理输入的结构 | 激活参数少不代表全部权重占用小 |
| Pretraining 预训练 | 用广泛数据学习通用表示和预测规律 | 通用能力不等于遵循用户指令或领域可靠性 |
| SFT 监督微调 | 用输入与目标输出继续训练模型 | 指令微调是典型用途，SFT 不限于指令任务 |
| LoRA | 用低秩增量适配部分权重 | 节约训练开销，但不会自动获得高质量数据 |
| QLoRA | 在量化基础权重上训练低秩适配器的一类方案 | 与“任何模型用4-bit推理”不是同一概念 |
| RLHF | 用人类反馈形成奖励信号并优化模型行为的流程家族 | 偏好更高不保证事实更正确 |
| DPO | 直接用偏好对优化策略的一种目标 | 不需要显式训练奖励模型，不等于没有偏好假设 |
| RL 强化学习 | 通过行动及奖励信号优化策略 | 监督模仿与强化学习目标不同 |
| RLVR | 利用可验证结果形成奖励的强化学习 | 易验证任务上的成功不自动迁移到开放事实问题 |
| Inference 推理执行 | 给定模型和输入计算输出的过程 | 不等于 reasoning 这种问题求解能力 |
| Reasoning 思维推理 | 多步推导、规划和检验等能力 | 可见解释未必忠实记录内部计算 |
| Prefill | 一次处理已有输入，形成后续生成所需状态 | 首字延迟还有排队、检索和网络时间 |
| Decode | 自回归模型逐步生成后续 token | 各序列内部有依赖，并不等于整台GPU只能处理一个请求 |
| KV cache | 缓存此前 token 的键和值以减少重复计算 | 不是跨会话长期记忆或答案缓存 |
| Prefix cache | 在条件匹配时复用相同输入前缀的计算 | 缓存隔离、键和失效规则仍需设计 |
| Quantization 量化 | 以较低数值精度表示权重或激活等 | 不等于减少参数数量，速度收益依赖硬件支持 |
| Distillation 蒸馏 | 用教师的输出、分布或轨迹训练学生 | 不同蒸馏设置的收益不能一概而论 |
| Temperature 温度 | 调节输出分布的平滑程度 | 低温不消除事实错误，也不保证端到端确定性 |
| Top-p | 保留累计概率达到阈值的候选集合的一类采样 | 不等于固定保留 p 个候选 |
| RAG 检索增强生成 | 从外部资料检索证据，再用于生成 | 向量检索只是可能的一环；不是把知识训练进权重 |
| Reranker 重排器 | 对候选结果做更精细相关性排序 | 召回阶段完全漏掉的文档通常无法被重排救回 |
| Groundedness 有据性 | 输出是否由给定证据支持 | 证据本身过期或错误时仍可能不正确 |
| Hallucination 幻觉 | 生成看似可信但不真实或无支持内容的现象 | 不应把所有风格差异或任务失败都叫幻觉 |
| Tool calling 工具调用 | 模型提出工具名和参数，由运行时执行 | 模型文本不是已经执行的真实结果 |
| Agent 智能体 | 在目标下循环选择动作、观察结果并继续决策的系统 | 有多个工具不必然构成自主 Agent |
| Workflow 工作流 | 开发者预先规定关键步骤和控制路径的流程 | 工作流可以包含模型，也可以包含受限 Agent |
| Memory 记忆 | 持续保留并检索相关状态、事实或经历的机制 | 会话历史、外部存储和权重更新是不同层次 |
| Prompt injection 提示注入 | 不可信内容试图改变系统行为或权限边界 | 与普通错误提示、用户合法指令的来源不同 |
| Guardrail 防护机制 | 输入输出检测、权限和执行约束等措施 | 分类器或提示词无法代替真正访问控制 |
| Benchmark 基准 | 固定或定义明确的任务与评价协议 | 排名是协议下的结果，不是通用能力证明 |
| LLM-as-a-Judge | 用语言模型依据标准评审其他输出 | 评审者会有偏差，需要与人工校准 |
| Recall@k | 前 k 个结果召回相关对象的比例 | 分母和相关性单位须先定义 |
| MRR / nDCG | 分别衡量首个相关结果排名、带等级相关性的排序质量 | 排序好不等于最终回答好 |
| Pass@k | k 次候选中至少一个通过验证的能力估计 | 与部署只允许一次尝试的成功率不同 |
| Calibration 校准 | 置信度与实际正确频率的一致程度 | 模型说“我有90%把握”并非已校准概率 |
| TTFT | 从请求开始到首个输出 token 的延迟 | 需要说明是否含网络、检索与排队 |
| TPOT / ITL | 每个输出 token 用时或相邻 token 间隔 | 平均值可能隐藏尾部停顿 |
| Throughput 吞吐量 | 单位时间内处理的请求或 token 量 | 提升吞吐可能增加单请求等待 |
| SLO | 服务目标，例如规定分位数下的延迟或成功率 | 模型离线准确率不能替代服务目标 |
| Distribution shift 分布变化 | 实际输入与开发或评测样本的分布不同 | 测试集固定不是一劳永逸 |
| Data contamination 数据污染 | 训练或优化过程接触了评测目标信息 | 同题改写、答案泄漏和近重复也可能污染 |
| FID / FVD | 比较图像/视频特征分布的一类自动指标 | 不是单张质量分，也不能证明物理或语义正确 |
| WER | 词级转写编辑错误率 | 不区分一个普通词与关键金额错误的业务代价 |
| MOS | 人工主观质量评分的平均值 | 必须报告听众、题目、设备和抽样协议 |

## 5.1 后端类比的用处与边界

上下文可以类比请求载荷和工作内存，权重可以类比程序内部长期形成的行为，RAG 可以类比读外部索引，工具调用可以类比 RPC，Agent 的循环可以类比有动态决策的任务调度器。这些类比有助于定位职责，但存在重要边界：模型不会像普通程序一样严格遵循你写出的自然语言规则；向量相似不等于关系数据库的精确相等；对话中声称成功不等于远端事务提交。

因此，复用后端经验时应迁移**契约、隔离、可观察性、幂等、超时、版本和回归**，而不要迁移“同输入必然同输出”“所有状态显式可见”“解释就是执行轨迹”的假设。将随机性限制在需要它的局部，把事实源、权限与实际执行状态保存在确定性系统中，是前文工程建议的共同基础。
